# 交付、文档验收与匿名

## 要求的来源

课程论文优先教师文件和明确约定。期刊/学校/出版社以本次实际读取的正式规范登记版本、网址/文件与核验日；原来源的期刊表、审稿周期、收录状态、字数、主办单位与国标年份只是历史线索，不当当前事实。无目标刊只交通用工作稿，不能声称“符合所有 CSSCI”。

全文交付通常有可编辑正文与引用清单，用户要求提交文件时给 DOCX/PDF 及简短检查报告。用户只要局部文字就不额外生成全套文件或封面。

## Word 的实现与检查

优先使用当前可用文档工具与学校模板。需要本地库时在 Codex 使用 workspace dependency 工具发现实际运行时，不猜绝对路径。内置转换入口 `toolbox.py docx <Markdown> --out <新.docx>` 使用总包独立实现的 `export_docx.py`，暂定 A4/常规中文样式；这些是可逆工作默认值，不是课程标准。原 S09 转换器另行保留，不能直接处理总流程稳定脚注键。

Markdown 工作稿 `[^N001]` 需要转为真正 `w:footnoteReference` 与 `footnotes.xml`，而不是底部手写编号、章节附注冒充页下脚注。原 S04 “右键把 [n] 转为脚注”不是可靠通用方法；要求真脚注时须正确转换或明确仍是工作稿，不把技术局限伪装为学校许可。多次引用同一来源的不同注释保留不同 N 编号。新转换器拒绝重复出现的同一脚注 key；需要再次出现时先建独立 N key 并复核。

检查中文 EastAsia 字体、正文与脚注字体、Heading 层级、页面尺寸与页边距、段间/行距、首行缩进、页码/分节、目录、脚注分隔与编号、链接和表格。内置导出器只覆盖其支持的 Markdown，不支持的复杂公式/表格/嵌套结构要换工具；不能静默丢内容。

**结构验收**：对照源文全文提取结果，确认标题/正文/引用一致；检查 DOCX 包中脚注关系、内容类型、标识引用与定义无缺失。XML 通过不是布局通过。

**视觉验收**：真实渲染 DOCX→PDF/逐页图片，逐页检查中文缺字、孤行、超出边界、空白页、脚注错位与表格断裂；修改后重渲染。当前环境无渲染能力就写“结构已检查，布局未验”，不能继承旧版 PASS。PDF 应可检索，长文加目录/书签并验证跳转。

渲染中文成批空白，或PDF提取结果反复出现同一汉字时，应区分源文件、字体和渲染引擎问题；先诊断日志及版本，再用实际可用的稳定工具独立复核并记录引擎，不凭XML检查判成稿可用，不改动用户全局环境来掩盖问题。内置导出可用 `--cn-font` 指定已安装且符合要求的字体；平台默认字体只是工作参数。

## 最终质量门

| 检查 | 通过依据 |
|---|---|
| 问题和论证 | 标题/引言/正文/结语一致，理由与重要异议已处理 |
| 来源与支持 | 当前用途原文/精确定位可回查，作者自论与来源性主张分开 |
| 法律 | 身份、版本、适用时点、条文/案号与沿革已核验 |
| 引注 | 正文标识/定义/来源对应，直接引语准确，再引正确 |
| 经验与图表 | 来源、口径、样本、计算、因果强度与图表一致 |
| 格式 | 符合实际目标文件；无规定时明示暂定值 |
| 文件 | 指定格式确实生成、内容未丢失，需布局的交付完成渲染复检 |
| 状态 | 待核/占位未隐去；未完成检查显式列出，不冒称终稿 |

`scripts/project.py audit` 仅做引注结构、占位、来源登记完整度、可选本地哈希等机械检查；既不能验证法律时效，也不能判断引文是否支持主张。零机械错误仍需人工核验。

## 匿名、隐私与外部动作

先定哪些是作者身份、哪些是学术来源，避免把文献作者姓名也删掉。检查正文、页眉页脚、批注、修订历史、文档属性、文件名、致谢、基金和自引中的识别线索；正则扫描只是辅助。待核标记不能因“匿名清洗”消除。

未发表正文、用户姓名、学校、联系方式及原始材料不进入公开示例/仓库。用户明确要求分享/投稿再做对应外部动作，本 skill 的调用不等于授权发布、上传、发信或替用户填报。期刊决策、作者信息和学术披露按实际要求与用户确认执行。
