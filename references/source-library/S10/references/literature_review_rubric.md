# Literature Review Rubric

Use this when planning, diagnosing, or revising a literature review. Course-supported rules should be checked against `key_principles.md`; other advice below is marked as general. When the user asks to search, import to Zotero, generate structured paper notes, or draft a review from collected sources, also load `literature_search_zotero_workflow.md`.

## Core Function

- [course norm] A literature review should analyze previous research to derive a worthwhile research problem, gap, hypothesis, or research plan.
- [course norm] It should summarize prior findings and methods, identify limits or disputes, and justify why the new study is needed.
- [general academic writing suggestion] The review should make the reader feel that the study is entering a live scholarly conversation, not merely reporting what was read.

## Pass / Partial / Fail Criteria

| Criterion | Pass | Partial | Fail |
|---|---|---|---|
| Relation to research question | Every cluster serves the question | Some clusters serve it, others are background | Review is about a different topic or broad background |
| Organization | Organized by debate, concept, variable, method, school, case, or period | Mixed organization, some author-by-author listing | Mostly "A says, B says, C says" |
| Source selection | Relevant, direct, important, authoritative/recent/first-hand sources | Some relevant sources but major gaps | Weak, random, second-hand, or unverifiable sources |
| Search scope | Search terms cover topic, question, concepts, case, method, and Chinese/English variants when search is requested | Some terms or databases are missing | Search relies on one vague keyword or only the title |
| Zotero/source traceability | Sources have verified metadata, Zotero item keys or supplied records, and clear collection/status | Metadata or import status is incomplete | Sources are invented, untraceable, duplicated, or treated as read only because they are in Zotero |
| Structured reading notes | Each source records question, theory/concepts, method/data, finding, contribution, limitation, and relation to this paper | Notes summarize findings but miss method, limits, or relation | Notes are only citations or copied abstracts |
| Synthesis | Shows consensus, disagreement, limits, and implications | Summarizes but evaluates lightly | Lists findings without analysis |
| Gap | Clear unresolved issue leads to this study | Gap is implied but vague | No gap or contribution logic |
| Hypothesis/design support | Variables, hypotheses, or framework are grounded in sources | Some support but key links missing | Model/hypotheses appear because data exist |

## Workflow

1. Identify the paper's research question.
2. List literature clusters needed to answer why the question matters.
3. For each cluster, record: consensus, disagreement, method limits, concept limits, and relation to the user's study.
4. Check whether foundational, recent, and directly relevant studies are represented.
5. If literature search is requested, create a search log, import verified records to Zotero when requested/confirmed, and make structured notes before drafting.
6. Write a gap statement in one of these forms:
   - Prior work explains X, but not Y under condition Z.
   - Prior findings conflict on X because they use different concepts/methods/cases.
   - Prior work studies A, but the present case/material reveals B.
   - Prior work has methods/data limits that this study addresses.
7. End the review by linking the gap to the research question, theoretical framework, or research design.

## Common Fixes

- Convert author-by-author paragraphs into claim clusters.
- Move general background into the introduction or cut it.
- Add transition sentences that explain why one cluster leads to the next.
- Replace broad "few studies exist" claims with specific statements about what is missing.
- Mark unsupported source claims as `Citation Risk` or `Evidence Gap`.
- Turn raw Zotero collections into a review matrix before drafting.
- Mark metadata-only or abstract-only sources so the review does not overstate what has been read.
