### 从选题到交稿，一套技能贯通中国法学论文写作

> 不只是让 AI “写一篇论文”，而是让它围绕真实法源、真实文献和可检验的理由链，把论文从一个想法推进为有依据、有结构、能修改、可交付的成果。

这是一个面向**中国法学学术写作**的整合型 Agent Skill。以中国法学课程论文为默认场景，同时支持开题报告、文献综述、期刊论文、学位论文和多章节长篇研究。

**你只需要调用这一个技能入口，不必自己拼接十套技能。** 它按当前任务加载研究、结构、论证、引注、表达、修订或交付模块，既能走完整流程，也能只解决眼前的一项难题。

**高质量的核心不是辞藻，而是：问题具体、法源准确、证据可追溯、论证有中间理由、修改不偷换立场。** 本项目将这些要求写进工作流，并用工具处理脚注、题录、版本和文件交付中的机械问题。

## 适合谁用

- **法学本科生、法律硕士和法学硕士**：课程论文、毕业论文、开题与答辩。
- **法学博士和研究者**：研究问题收束、规范论证、论文结构、文献组织与期刊适配。
- **已有初稿的人**：解决目录机械、观点空泛、引注失配、反馈难落实或越改越乱的问题。
- **长篇项目作者**：多章接续、术语和数值一致性、批次台账与材料冻结。

适用于民商法、刑法、行政法、宪法、诉讼法、经济法、竞争法、国际法及法理学等方向；具体部门法结论依赖本次任务提供和核实的材料，不靠固定模板替代专业判断。

不把学术论文流程混用于诉状、合同、个案代理等法律实务文书。

## 功能全景

| 模块 | 具体可以做什么 | 可获得的成果 |
|---|---|---|
| **1. 需求诊断与项目定锚** | 识别课程、学校或期刊要求；确定对象、字数、截止日、材料边界、适用法律时点；接续既有项目 | 项目卡、主问题、暂定回答、工作计划、缺口清单 |
| **2. 选题与学术增量** | 把宽泛主题收束为可回答的法律问题；判断是否有争点、材料和可证明的增量；选择研究类型 | 候选选题比较、范围说明、问题意识和贡献定位 |
| **3. 结构与提纲** | 选择六种贡献结构，区分贡献结构与研究方法；检查章节职责、层级、前后衔接及结论对应 | 有论证任务的提纲，而不是“现状—问题—原因—对策”的空目录 |
| **4. 文献检索与材料接力** | 设计中英文检索式、追踪引文；接收知网等平台导出的题录和 PDF；去重、筛选、分级 | 检索记录、题录 TSV、核心/支持/储备文献清单 |
| **5. 精读与文献综述** | 区分题录、摘要、片段和全文；记录原句、位置、作者观点和可支持的命题；围绕争议组织综述 | 精读笔记、综述矩阵、争点地图、研究现状与空白 |
| **6. 法源与证据核验** | 核对法律身份、版本、适用时点和沿革；区分法律、司法解释、纪要、政策、案例与学说；检查案号、事实与裁判理由 | 来源登记、法源版本表、案例卡、用途与证据上限 |
| **7. 正文写作与法律论证** | 从具体争议切入；建立“主张—材料—理由—限度”；处理规范解释、要件、证明责任、程序和救济；回应竞争解释与反例 | 引言、章节、完整工作稿、论点—证据—引注表 |
| **8. 比较法与实证方法** | 审查功能等值和制度移植条件；设计样本、问卷、访谈、编码和数据口径；区分描述、相关和因果 | 方法说明、调查/编码方案、比较维度、结论适用边界 |
| **9. 中文与外文引注** | 按资料类型生成、修改和检查引注；处理直接引用、概括、转引、首次及再次引用；按目标体例统一格式 | 脚注、参考文献草案、引注审查报告、待补字段 |
| **10. 框架与语言优化** | 四层检查结构、标题、术语和论证；减少机械对称、空泛连接和模板腔；保持法律术语、立场与限定条件 | 修订正文、目录重构、具体修改理由与结构变化说明 |
| **11. 导师/审稿反馈落实** | 对齐批注所指版本；合并重复意见、标明冲突；逐项修改并记录继承关系；检查版本冗余与健康度 | 反馈落实表、新旧版本说明、修订稿、待裁定问题 |
| **12. 模拟审稿与匿名材料** | 从稿件本身检查研究问题、论证、来源和体例；生成审稿任务包；扫描隐私线索、制作匿名副本 | 审稿意见、审稿任务书、匿名处理说明、缺陷优先级 |
| **13. 学位与长篇管理** | 分批起草、跨会话恢复；登记创新点、已发表成果、自引、数据冻结、图表与关键数值；支持论文转专著的结构调整 | 长篇台账、批次成果、术语表、图表证据卡、合并方案 |
| **14. Word 与文件交付** | 导出中文标题和正文样式、简单表格、真实 Word 脚注；检查正文与表内脚注；规划 PDF 渲染与逐页验收 | Markdown / TSV / JSON / DOCX；具备转换工具时进一步交付 PDF |
| **15. 投稿与跨语种扩展** | 提炼题名、摘要和关键词；按正式要求制作目标期刊卡；做英文摘要、IRAC/CREAC辅助与答辩问答 | 投稿检查清单、中英文摘要、选刊比较、答辩提纲与问答 |

六种贡献结构的具体选择见 [选题与结构](references/topic-structure.md)；全部 **72 项能力路由**见 [能力矩阵](references/capability-matrix.md)。其中有些是方法指导，有些有脚本支持，并非全部自动执行。

### 引注能处理哪些材料？

中文图书、译著、期刊论文、文集、报纸、古籍、网络文章、公众号、App、影音资料、学位论文、会议论文、未刊材料、档案、访谈、私人通讯、法律规范、官方文件、裁判与统计数据；另含英文及法、德、意、俄、日等外文资料的规则参考。

支持法学引注工作体例，以及按任务选择的 GB/T、Bluebook 等体例草案转换。**先确定目标要求，再处理格式；缺少的作者、页码、文号或案号不会由格式工具补造。**

## 质量控制

### 不是“生成得像论文”，而是“经得起追问”

1. **不编资料**：不编文献、页码、案号、法条、调研、访谈和数据。
2. **读到多少，说到多少**：摘要不冒充全文；已收藏不等于已读，已读不等于支持当前论点。
3. **三轴登记**：相关度 `CORE/SUPPORT/RESERVE`、读取范围 `METADATA/ABSTRACT/EXCERPT/FULLTEXT`、用途核验 `VERIFIED/PARTIAL/LEAD_ONLY/UNUSABLE` 分开管理。
4. **法源带时间**：事实发生时、法律适用时、研究截止时和核验日分别核对。
5. **论证有桥梁**：不能用“因此”“可见”掩盖前提缺失，不能从一个案例推出所有案件。
6. **修订不换观点**：局部修改保留原有语义和限定；新增实体内容说明依据。
7. **引注可追溯**：稳定来源身份与脚注出现编号分离，保留每次引用的位置和用途。
8. **不覆盖原稿**：生成任务使用新输出；待核事项保留到真正解决。
9. **提交有验收状态**：区分工作稿、待核工作稿与完成所列验收的提交版。

本项目以提高写作质量和可核验性为目标；未进行真实论文盲评、成绩或录用率评测。不承诺“保证高分”“保证录用”“保证查重/AI检测结果”。语言诊断不等于鉴定文本是否由 AI 生成。

## 安装与调用

### Codex：推荐安装

在终端执行（目标目录已有旧版时先备份，不要覆盖正在使用的修改）：

```bash
git clone https://github.com/lyyrebecca/chinese-law-paper-workflow.git \
  "$HOME/.codex/skills/chinese-law-paper-workflow"
```

重新打开会话或按客户端方式刷新技能后，输入：

```text
使用 $chinese-law-paper-workflow，帮我完成这篇中国法学论文。
```

也可以自然描述任务，例如“帮我写竞争法课程论文”“核查这篇法学论文的引注”。客户端是否自动发现取决于其技能加载机制；显式指定最直接。

### Claude Code / 其他支持本地 Skill 的客户端

Claude Code 可将仓库克隆到个人技能目录：

```bash
git clone https://github.com/lyyrebecca/chinese-law-paper-workflow.git \
  "$HOME/.claude/skills/chinese-law-paper-workflow"
```

其他客户端可下载 [Release ZIP](https://github.com/lyyrebecca/chinese-law-paper-workflow/releases/latest)，解压后把整个 `chinese-law-paper-workflow` 文件夹导入其支持的技能目录。保留 `SKILL.md`、`references/`、`assets/`、`scripts/` 的相对结构；不要把十份 `ORIGINAL_SKILL.md` 分别安装。不同客户端的发现、工具权限和渲染能力需要实际确认，本项目不声称已逐个平台验收。

### 不运行脚本也能用

选题、提纲、论证、研究指导、修订和引注规则均可通过读取 Markdown 使用。Python 只用于需要脚本的机械任务。

## 直接复制的使用示例

### 1. 从零开始写课程论文

```text
使用 $chinese-law-paper-workflow。
我要写一篇竞争法课程论文，约 8000 字，研究行业协会协调停工限产的反垄断问题。
我会提供课程要求、现行法和相关案例。请先收束研究问题、识别材料缺口，
然后完成提纲、论证、正文、引注、修改说明和交付检查。
材料足够就连续推进；无法核实的地方保留待核，不要编造页码或案号。
```

### 2. 做开题与选题判断

```text
使用 $chinese-law-paper-workflow。
我的研究方向是个人信息保护，附件是选题想法和已有材料。
请比较候选问题的争议价值、材料可得性与可证明的贡献，
给出主问题、范围、暂定答案、章节职责、研究方法与下一步检索方案。
```

### 3. 用题录和 PDF 完成综述

```text
使用 $chinese-law-paper-workflow。
附件是导出的题录和下载的论文 PDF。
请去重分级，区分已读范围，建立精读笔记与综述矩阵，
围绕争议组织研究现状；每项观点写明对应材料与具体位置。
```

### 4. 修改初稿、减少模板腔

```text
使用 $chinese-law-paper-workflow 修改附件初稿。
先检查研究问题、框架和推理，再处理引注与语言。
不要把我的立场改强，不增加未经证明的例外和法律后果。
请交付修订稿、重要修改理由、反馈落实表和仍需补证的清单。
```

### 5. 只核查引注

```text
使用 $chinese-law-paper-workflow，只检查引注，不改正文观点。
按我提供的期刊要求，逐项核对资料类型、著录字段、引用定位、
正文主张与来源支持关系，区分格式问题与尚未核实的问题。
```

### 6. 接续学位论文

```text
使用 $chinese-law-paper-workflow 接续附件项目。
先读取项目卡、已确认目录、批次台账、来源登记与待核清单，
再继续下一节；维护术语、数值和图表编号，不凭聊天记忆补文献。
```

### 7. 生成交稿文件

```text
使用 $chinese-law-paper-workflow。
正文与资料已经提供，请按学校模板生成 Word，使用真实脚注，
保留常规版并另做匿名副本；检查标题、表格、脚注对应与文档属性。
具备 PDF 转换与渲染能力时，再输出 PDF 并逐页验收。
```

## 一次完整任务会交付什么

按任务规模取舍，不强制每次生成全套表格：

- 论文正文、可用章节或明确标注缺口的工作稿。
- 对应脚注与所需参考文献。
- 项目卡、来源登记和核心材料的精读/综述记录。
- 论点—材料—理由—引注关系表。
- 重要修改说明、导师或审稿意见落实表。
- 待核、待补和待用户裁定事项。
- 用户要求且环境支持的 DOCX / PDF，以及实际完成的验收说明。

轻量课程论文用最少必要记录；学位、书稿和长期项目再启用完整台账。

## 内置脚本工具

在仓库根目录运行；以下路径均相对于当前目录：

### 项目初始化与审核

```bash
# 新建课程论文项目；拒绝覆盖非空目录
python3 scripts/project.py init ../my-law-paper --title "我的论文题目"

# 长篇项目
python3 scripts/project.py init ../my-thesis --title "我的学位论文" --profile longform

# 只读检查脚注、来源登记和文件漂移
python3 scripts/project.py audit ../my-law-paper/03_正文/论文_v1.md \
  --registry ../my-law-paper/02_研究/sources.json --final --check-files --format json
```

初始化后的实际文件以新项目内生成目录为准；`--final` 是更严格的机械检查，不是对法律正确性和学术质量的自动认证。

### 统一工具箱

```bash
python3 scripts/toolbox.py --help
python3 scripts/toolbox.py <子命令> --help
```

| 子命令 | 用途 |
|---|---|
| `parse-cnki` | 解析 RefWorks/EndNote 文本题录，生成 TSV 并去重 |
| `format-refs` | 从 TSV 生成法学或 GB/T 工作条目 |
| `validate-refs` | 检查原数字式脚注或顺序编号的结构 |
| `health` | 冗余、长句和版本健康线索检查 |
| `language-signals` | 机械或空泛表达线索检查，不作 AI 来源判断 |
| `legal-signals` | 法律术语、旧法和缺口的正则提示，不代替现行法核验 |
| `privacy` | 扫描文件或目录中的隐私线索 |
| `normalize` | 在新副本中规范标点，之后仍需复核引语和外文 |
| `renumber` | 重排 `[n]` 式文末参考文献，保留原稿 |
| `review-packet` | 生成审稿稿与任务说明；可做元信息匿名 |
| `docx` | 导出真实脚注 Word，包括简单表格内的脚注 |
| `pdf-text` | 提取 PDF 的分页文本；扫描件另需 OCR |
| `structure-check` | 检查结构变化声明，区分真实节点变化与只换词 |

```bash
python3 scripts/toolbox.py docx paper.md --out paper-submission.docx
python3 scripts/toolbox.py review-packet paper.md --out review-round-1 --anonymize
python3 scripts/toolbox.py parse-cnki exported.txt --out references.tsv
```

统一审核支持 `[^N001]` 稳定脚注键；部分上游数字式工具只处理数字编号，不能混用。DOCX 导出支持标题、简单段落、简单表格、粗体、斜体及脚注；复杂图片、代码、公式等超出支持范围时会拒绝转换，不默默丢内容。期刊式与脚注式输出要求不同，先看 `--help` 与 [工具说明](references/tools.md)。

深度工具还包括目录提取、词汇和静态语料维护、结构校验，以及采用独立书稿格式的批次校验、数据图和 Word 合并。它们不必在普通论文中运行；所需输入协议和依赖见对应源码与模块说明。

## 支持能力与运行条件

| 能力 | 需要什么 |
|---|---|
| 写作、修订、结构与引注方法 | 能读取本地 Skill 文件的 AI 客户端；无需 Python |
| 初始化、统一审核、多数文本工具 | 推荐 Python 3.10+；以实际工具兼容性为准 |
| Word 导出 | `python-docx` 与 `lxml`，可用 `python3 -m pip install -r requirements-docx.txt` |
| PDF 提取 | PyMuPDF 或 pypdf，可选安装 `requirements-pdf.txt`；OCR 不是内置功能 |
| 统计图与原生长篇工具 | 所用脚本的独立依赖与格式；不是总流程轻量模板直接转换 |
| 实时法源、文献与期刊核验 | 客户端可用的网络、检索或数据库访问能力 |
| 知网等订阅资料 | 已授权访问；不能访问时由用户导出题录、下载 PDF 后交接 |
| Zotero / Obsidian | 任务需要时使用相应可用工具与用户指定的操作范围；不是必装项 |
| PDF 转换与逐页渲染 | 客户端或本机另有可用转换/渲染能力；脚本工具箱本身不直接导出 PDF |

**“一套技能覆盖全流程”指工作方法、路由、模板和常用工具集中，不等于无需资料、数据库或文档运行环境。** 无法核验或转换时应交可继续处理的材料与缺口说明，而不是宣称已经完成。

## 项目结构

## 验证与发布

```bash
python3 scripts/test_workflow.py
python3 scripts/check_release.py
```

回归覆盖项目初始化、防覆盖、来源状态、脚注定义与引用、待核保留、文件漂移、题录去重、编号处理、真实 Word 脚注、匿名副本和结构声明等。发布检查另核对文件清单、哈希、个人路径、旧安装元数据与非许可区域的历史账号残留。

测试通过证明所测工具行为，不代表真实法源已在线核实，也不等于论文内容经过独立法学专家评审。完整条件与结果见 [VALIDATION.md](VALIDATION.md)；公开发布 ZIP 可在 [Releases](https://github.com/lyyrebecca/chinese-law-paper-workflow/releases) 下载。
